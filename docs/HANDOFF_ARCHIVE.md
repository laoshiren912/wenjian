### 根本原因与定位证据

- 最早失败发生在集成脚本首次 `aim_right()` 后的“Mouse position drives aim”，随后剑/长矛真实伤害、弓箭命中/飘字/单目标清理等断言连带失败；切武器、冷却与体力检查本身仍通过。不是从伤害计算或攻击范围判定开始出错。

## 历史修复：HUD 与世界攻击输入隔离（2026-10-27）

- 真实原因：输入事件先经过 `_input`，再由 GUI 处理，未被消费的事件才进入 `_unhandled_input`。原 Player 在物理帧直接轮询全局 `Input.is_action_pressed("attack")`；GUI 消费鼠标事件不会清除该状态。按钮默认在松开时发出 `pressed`，因此点击暂停按钮的按下到松开之间仍可能攻击并扣除体力。不是按钮缺少鼠标阻挡，也不能仅靠 `accept_event()` 解决。
- 修复：Player 仅在 `_unhandled_input` 收到 GUI 未消费的攻击按下事件时记录按住状态；物理帧同时检查该状态与全局按住状态。松开事件在 GUI 之前的 `_input` 清除记录；节点暂停或窗口失去焦点时也清除记录，防止弹窗吞掉松开事件、恢复后延续攻击。正常游戏区域按住左键连击仍保留，暂停后需重新按下左键才恢复攻击。
- GUI 按钮原有事件消费、点击时机和布局保持不变；该处理统一适用于 HUD、开局、暂停/属性、升级、死亡/胜利结算界面。
- 修改文件：`scripts/player.gd`、`tests/ui_click_probe.gd`、`tests/integration.gd`、`tests/normal_session.gd`、`HANDOFF.md`。集成测试和正常难度驱动补齐鼠标事件分发，不再只修改全局 Input 状态；没有删减原有 44 项断言。

2. 依次按 1/2/3，边退边瞄准攻击同一类敌人。检查剑高伤单体、长矛较低伤群攻、弓箭远程单体及可见箭矢；从障碍两侧攻击，确认墙体阻挡一致。检查金色/红色扣血数字、脚下蓝色经验提示和命中/受伤震动。持续按住攻击，确认攻击间隔正常、体力始终为 100；反馈首个击杀和首次升级的时间。当前普通游戏没有体力消耗动作，不能用普攻测试扣除/恢复，预留接口由自动夹具覆盖。
3. 先不攻击金色圆形，观察其中立行为，再攻击触发反击；对比红色菱形的主动追击、攻击预警与受击反馈。避免一直停在出生点。
4. 击败敌人并靠近蓝色经验晶体；在不同升级中分别选择力量、迅捷、活力，用 Tab 对比实际属性，确认升级期间敌人和计时暂停，选择后恢复。
5. 用 Tab、Esc 和 HUD 按钮反复暂停/继续；特别留意点击 HUD 是否意外攻击或消耗体力。自然死亡后核对结算，再分别用 R、Enter、鼠标按钮重开。
6. 至少尝试一局主动战斗到 03:00，以及一局只移动绕圈。反馈死亡时间、所用武器/升级、是否觉得开局过急、战斗是否值得参与、卡点位置和错误输出。两种策略都需要真人判断，不能用脚本结果代替。
